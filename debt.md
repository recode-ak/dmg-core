### DEBT-2: «только чтение» заместителя не запрещает запись из query UC
- **Место:** `src/app/use-case/use-case-from-def.ts` — шаг допуска заместителя отказывает только command UC
- **Признак:** `person\.readOnly && this\.def\.type === 'command'`
- **Причина:** query UC по контракту не пишет, но платформа это не проверяет: query с побочным эффектом (запись через репозиторий, вызов внешней системы) пропускает заместителя `readOnly`. Проверка «query не пишет» в рантайме (UoW query без `save`/`emit`) — отдельное решение; MAN-14 закрывает только вложенный command.
- **Триггер:** первое приложение включает «только чтение» заместителю
- **Критерий снятия:** UoW query UC отвергает запись и публикацию (или `DefChecker` — по `touches`), тест заместителя `readOnly` на query с записью — отказ

### DEBT-3: тексты проблем валидации повторяют введённое значение
- **Место:** `src/app/use-case/use-case-from-def.ts` — `issues()` отдаёт `issue.message` valibot как есть
- **Признак:** `message: issue\.message`
- **Причина:** сообщения valibot по умолчанию содержат полученное значение (`Invalid email: Received "secret@"`). Они уходят в payload `INPUT_VALIDATION` и `OUTPUT_VALIDATION`, оттуда — в лог операций без маскирования (схема `Issues` полей `F.sensitive` не знает, `RecordMask.error` payload не трогает) и в `ErrorText` (D-99). Решение принято (Нурболат, 2026-11-16, по аудиту безопасности Ф4 трека `dmg-graph-ext`): тексты проблем — нейтральные, без введённого значения; сообщение строится по `issue.type` и `issue.expected`, без `issue.received`, либо берётся заданное автором схемы. Правка меняет существующие тексты ответов и записей лога, поэтому идёт отдельным срезом, а не в `dmg-graph-ext`.
- **Триггер:** первый потребитель показывает человеку строки полей `ErrorText` или во входе UC приложения появляется поле `F.sensitive` — что раньше. Состояние на 2026-11-16: `dmg-ui` (исполнитель экрана, с v0.1.0) показывает только главную строку `ErrorText.summary`, строки полей не берёт — триггер не наступил; наступит, когда канал `dmg-ui` начнёт показывать замечания по полям отказа UC
- **Критерий снятия:** значение невалидного поля не встречается ни в payload ошибки валидации, ни в записи лога операций, ни в `ErrorText` — тест на поле `F.sensitive` с неверным форматом
