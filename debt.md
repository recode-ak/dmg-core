# Технический долг пакета `dmg-core`

**Назначение:** осознанные отступления от правил и решений пакета. Файл в tarball не входит: это реестр разработки пакета, а не документация потребителя.

**Последний выданный ID:** DEBT-5

Реестр — allowlist (D-84): код к записи привязывают её поля, а не маркеры в коде. Сверку выполняет `DebtChecker` из `dmg-core/arch` (ARC-12) в тесте `src/arch/debt-checker.test.ts` (в `bun run check`). Новый ID — следующий после «Последнего выданного», строка правится тем же коммитом; номера не переиспользуются, закрытая запись удаляется.

```
### DEBT-<n>: <краткое название>
- **Место:** `<glob>`, `<glob>` — <пояснение>
- **Признак:** `<регулярка, флаг m>`
- **Корень:** `<glob>` — где признак вне Места — долг без записи (нет поля — весь код)
- **Причина:** <почему нельзя убрать сейчас>
- **Погашает:** <трек>            ← или **Триггер:** <условие>
- **Критерий снятия:** <что должно исчезнуть>
```

**Долг тестов здесь не ведётся:** сверяется код без тестов. Лишние и дублирующие тесты удаляются сразу, без записи (TST-08, D-105).

ID в коде — только в строке `biome-ignore`. Проверяемый код — `src/` и `scripts/` без тестов; маркеры временности («Временное решение», «Уходит с миграцией», «ВРЕМЕННЫЙ») допустимы только в Месте записи (кроме `scripts/` и самого `DebtChecker`).

### DEBT-2: «только чтение» заместителя не запрещает запись из query UC
- **Место:** `src/app/use-case/use-case-from-def.ts` — шаг допуска заместителя отказывает только command UC
- **Признак:** `person\.readOnly && this\.def\.type === 'command'`
- **Причина:** query UC по контракту не пишет, но платформа это не проверяет: query с побочным эффектом (запись через репозиторий, вызов внешней системы) пропускает заместителя `readOnly`. Проверка «query не пишет» в рантайме (UoW query без `save`/`emit`) — отдельное решение; MAN-14 закрывает только вложенный command.
- **Триггер:** первое приложение включает «только чтение» заместителю
- **Критерий снятия:** UoW query UC отвергает запись и публикацию (или `DefChecker` — по `touches`), тест заместителя `readOnly` на query с записью — отказ

### DEBT-3: тексты проблем валидации повторяют введённое значение
- **Место:** `src/app/use-case/use-case-from-def.ts` — `issues()` отдаёт `issue.message` valibot как есть
- **Признак:** `message: issue\.message`
- **Причина:** сообщения valibot по умолчанию содержат полученное значение (`Invalid email: Received "secret@"`). Они уходят в payload `INPUT_VALIDATION` и `OUTPUT_VALIDATION`, оттуда — в лог операций без маскирования (схема `Issues` полей `F.sensitive` не знает, `RecordMask.error` payload не трогает) и в `ErrorText` (D-99). Решение принято (Нурболат, 2026-11-16, по аудиту безопасности Ф4 трека `dmg-graph-ext`): тексты проблем — нейтральные, без введённого значения; сообщение строится по `issue.type` и `issue.expected`, без `issue.received`, либо берётся заданное автором схемы. Правка меняет существующие тексты ответов и записей лога, поэтому идёт отдельным срезом, а не в `dmg-graph-ext`.
- **Триггер:** первый потребитель показывает человеку строки полей `ErrorText` или во входе UC приложения появляется поле `F.sensitive` — что раньше. Состояние на 2026-11-16: `dmg-ui` (исполнитель экрана, с v0.1.0) показывает только главную строку `ErrorText.summary`, строки полей не берёт — триггер не наступил; наступит, когда канал `dmg-ui` начнёт показывать замечания по полям отказа UC
- **Критерий снятия:** значение невалидного поля не встречается ни в payload ошибки валидации, ни в записи лога операций, ни в `ErrorText` — тест на поле `F.sensitive` с неверным форматом

### DEBT-4: проверка файлов не сверяет суффикс ↔ вид манифеста ↔ имя и место теста
- **Место:** `src/arch/file-checker.ts` — `FileChecker` проверяет пары «контракт ↔ реализация» (MAN-10), входы модуля (ARC-04), фейки (TST-07); суффикс файла, имя Def (`<Имя><Вид>Def`) и тест рядом со своим файлом не проверяются
- **Признак:** `^export class FileChecker\b`
- **Причина:** CODE-01 («структура и имена по naming.md») проверяют ревью и пары MAN-10; файл с неверным суффиксом или Def с именем не `<Имя><Вид>Def` проходят `arch:check`. Пакет `dmg-ui` проверяет это тестом (`UiFileNames` во входе `dmg-ui/testing`, правило `NM-01`, D-UI-112): суффикс ↔ вид по объявлению, имя, папка модуля, форма теста рядом, один вид на файл — и покрывает больше случаев
- **Триггер:** второй потребитель включает проверку имён из `dmg-ui` или трек `gen`/`sync` описывает виды в общем формате
- **Критерий снятия:** `ArchChecker` падает на подложенных нарушениях (неверный суффикс, имя Def ≠ `<Имя><Вид>Def`, тест вне каталога своего файла), зелёный на пакете; по тесту на каждый случай

### DEBT-5: нет шва исполнения удалённого модуля
- **Место:** `src/app/api-app/api-app.ts` — `ApiApp` строит фасад зависимости только из модуля своего процесса: удалённую зависимость не подключить
- **Признак:** `но фабрики \$\{dep\.name\} в приложении нет`
- **Причина:** вынос модуля в сервис (GR-01) предусмотрен решениями и раскладкой, но вживую не проверяется (D-109): фасада над `ModuleApi` для модулей монолита, зависящих от вынесенного, HTTP-транспорта и доставки событий между процессами в пакете нет. Писать шов без первого выноса — гадать о его форме; что в этот момент делается руками — `docs/guides/extract-module.md`
- **Триггер:** первый вынос модуля в сервис или HTTP-транспорт в пакете — что раньше
- **Критерий снятия:** модуль монолита получает фасад к модулю в другом процессе, вызывающий код не меняется; события доставляются между процессами; тест на два процесса или транспорт-заглушку; GR-01 — «проверен вживую»
