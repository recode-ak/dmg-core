# Тестирование

**Назначение:** общие правила тестов. Правила с ID — раздел TST в [rules.md](./rules.md).

---

## 1. Принципы

- **TDD:** тест пишется до кода; покрытие > 80%.
- **Изоляция:** тесты не зависят друг от друга и от порядка; состояние — с нуля (`beforeEach` или свежие экземпляры).
- **Размер:** 10–20 строк; подготовку данных — в хелперы. Тест — документация поведения.
- **Группировка:** `describe` по методу/операции, `it` — по ветке поведения.
- **Один тест — одна причина падения.**

## 2. Проверка отказов

Проверяется **конкретная ошибка**, а не факт отказа:

```typescript
const res = task.complete(at);
expect(res.ok).toBe(false);
expect(res.ok ? undefined : res.error.code).toBe('TASK_ALREADY_DONE');
```

Хелперы из `dmg-core/testing`: `expectErr(res, 'TASK_ALREADY_DONE')` возвращает ошибку, суженную по коду; `expectOk(res)` — значение. Не зависят от раннера, при несовпадении бросают.

## 3. Пирамида

| Уровень | Что тестируется | Объём |
|---|---|---|
| **Схемы** | своя логика схемы: `refine`/`transform`, отказ прежних форм записи, схема state, разбираемая при чтении хранилища. Приём и отказ полей платформы (`F.uuid`, `picklist`, `variant`, `expectedVersion`) не тестируются — их держат платформа и вызывающие | по логике |
| **Ar** | каждая ветка `Ok`/`Err` мутирующих методов, переходы статусов, события; подключение схемы — 1–2 теста | максимальный |
| **Policy** | каждое правило: allowed и denied, роли, свой/чужой, контекст | все правила |
| **DCS / DQS** | сценарии координации и вычисления на готовых агрегатах | все методы |
| **Репозиторий** | контракт: restore/snapshot, поиск, `undefined` при отсутствии; временный каталог | контракт |
| **UC / ER / Job** | цепочки: нет актора → `UNAUTHORIZED`, нет сущности → `*_NOT_FOUND`, политика → `ACCESS_DENIED`, успех → регистрация в UoW и события; каждая собственная ошибка. Порты — фейки (`MemoryRepo`, `StubFacade`) | по ошибкам |
| **Модуль** | smoke: один успешный вызов каждого UC на реальных репозиториях (временный каталог) | по UC |
| **Контрактные** | граф и правила MAN/ARC/ERR — `arch:check` в `check`; состав Def (`errors`, `emits`, `calls`) руками не повторяется. В тестах модуля — один тест состава: список UC и `dependsOn` | автоматически + 1 на модуль |

## 4. Моки

- Домен не мокается: он чистый, тесты работают с настоящими агрегатами.
- В прикладном слое мокаются порты (репозитории, фасады) — типизированно, без `any`.
- Время (D-34): домен получает момент аргументом операции (`task.complete(at)`) — в тесте Ar это просто константа. Прикладной слой берёт его из часов приложения (`this.now()` в UC/ER/Job); в тесте — `testAppContext({ at })` и `ctx.setNow(ts)` (`dmg-core/testing`). Глобальных часов нет, `Date` напрямую не читается.
- Пирамида хранилища: UC/ER/Job — фейк порта; репозиторий (контракт, каждая выборка) и smoke модуля — настоящий репозиторий во временном каталоге; e2e UI — настоящие репозитории.
- Фейк порта — `<A>RepoFake` в `<a>/<a>.repo.fake.ts` рядом с портом (создаёт `gen aggregate`): наследник `MemoryRepo` из `dmg-core/testing`. `save` сверяет версию, как настоящий репозиторий (`VersionConflict`); начальные записи — `seed(...)`; записанное — `saved` («ничего не записано» — `saved` пуст); чтение — `restored(uuid)`; сбой записи — `failOn(uuid)`. Тип снапшота — `StateOf<typeof <A>ArDef>` (DOM-01). Выборку `find*` фейк не реализует: метод порта объявлен `this.unanswered(...)`, ответ тест задаёт присваиванием (`tasks.findDone = async () => [...]`); корректность выборки — контрактный тест репозитория. Образец — `src/testing/example/app/todo/task/task.repo.fake.ts`.
- Готовые `testAppContext` (шина — `RecordingBus`, логгер — `MemoryLogger`), `MemoryBus` (доставляет события подписчикам), `MemoryRepo`, `StubFacade`, `expectIdempotentReaction` — для UC/ER без реального приложения (`src/testing/index.ts`); учебный модуль — `src/testing/example`.

## 5. Один уровень на правило (TST-08)

Рефакторинг не меняет функционал — число тестов не должно расти так, будто он добавлен.

- Логика переезжает (сборка ответа из UC в DQS, правило в Ar или Policy, legacy → Def) — её сценарии **переезжают**, а не копируются: у вызывающего они удаляются в том же шаге.
- У вызывающего остаётся своя ответственность: для UC — загрузка, вызов Policy, ошибки, `callers`, вход, запись в UoW; плюс один сквозной сценарий, что вызов доходит до нижнего уровня.
- Удаление дубля — не потеря сценария: в отчёте список «удалён → где покрыт» (файл, `it`), ревьюер сверяет.

- Один сценарий — один файл: новый файл «на новое поле» или «после переезда» не заводится рядом со старым — сценарии дописываются в существующий, старый файл удаляется.

## 5.1 Тест проверяет код модуля (TST-09)

Вопрос к тесту: какая ошибка в коде модуля уронит его, и только его? Нет такой — тест не пишется. Не тестируются:

- поведение платформы: разбор схем, `UNAUTHORIZED` без субъекта, `VersionConflict`, «событий нет» у операции, которая их не поднимает;
- фейк, стаб или фикстура: фильтр выборки, который делает фейк, — контракт репозитория;
- тавтология: константа против той же константы, ожидание, посчитанное тем же рабочим кодом, однострочный геттер, пустой вход на `filter`/`map`;
- вопрос Ar с единственным потребителем, покрытым тестом, — проверяется через потребителя;
- тексты `label` ошибок — видимые пользователю тексты проверяют тесты UI.

Тест мёртвого экспорта — сигнал удалить код, а не только тест.

## 6. Защита от регресса и чистота правок

**Критично:** реализация, исправление или рефакторинг не приводят к регрессу функционала вне задачи.

- **Запрещено** менять функции и тесты вне области задачи.
- **Исключение:** если правка соседнего кода необходима (критическая ошибка или требование задачи) — сообщить владельцу задачи и получить явное разрешение. Агент-исполнитель в этой ситуации останавливается и возвращает эскалацию.
