# Граф приложения

**Назначение:** формат графа — ядро (`Graph`, поставщики, `id`, документ `graph.json`), поставщик домена (дерево `id`, виды узлов и рёбер, внешние `id`) и команда `dmg-core graph`. Экспорт — `dmg-core/graph`. Решения — D-92, D-95, D-96, D-97 ([decisions.md](../decisions.md)). Правила проверок графа — MAN-15, MAN-16, ARC-13 ([rules.md](./rules.md)).

---

## 1. Ядро

- **Поставщик** — порт `GraphProvider`: `name` (непустая строка), `version`, `kinds()` — виды узлов и рёбер (`GraphKinds`: `nodes`, `edges`; вид — `kind`, `label`, `description`, необязательная схема `props`), `contribute()` — вклад (`nodes`, `edges`), необязательный `rules?()` — правила для `arch:check` (ядро их не читает, в документ они не пишутся).
- **Сборка** — `new GraphBuilder().add(p1).add(p2).build()`: двухфазная (сначала виды всех поставщиков, затем вклад), порядок `add` на результат не влияет; падает на первой ошибке (`GraphError`, §6).
- **Виды.** Вид регистрирует один поставщик; пространства видов узлов и рёбер раздельные; имя вида — по правилу сегмента `id` (§2). Элемент вида ставит любой поставщик: `provider` элемента — кто его поставил, а не кто объявил вид.
- **Свойства** (`props`) — выход схемы вида; у вида без схемы — `{}`, непустые свойства — отказ. JSON-совместимость свойств — ответственность схемы поставщика.
- **Видимость** — `visible` узла: показывать ли узел людям; не задано — `false`. У ребра поля нет.
- **Рёбра.** `from` — узел графа; `to` — любой валидный `id`: не узел — внешняя ссылка (`externals()`), сборку не роняет; отличить её от опечатки — дело правил проверок. Идентичность ребра — тройка `(kind, from, to)`.
- **Чтения `Graph`:** `nodes()`, `edges()`, `node(id)`, `roots()`, `children(id)`, `ancestors(id)` (от родителя к корню), `outgoing(id, kind?)`, `incoming(id, kind?)` (принимает и внешний `id`; неизвестный `id` — `[]`), `externals()`, `liftToKind(kind)`, `liftToDepth(depth)`, `mount(child, under)`, поле `providers`. Граф неизменяем.

## 2. `id` — путь от корня

- `GraphId`: сегменты `^[A-Za-z0-9][A-Za-z0-9._-]*$` через `/`, регистр значим.
- Родитель — `id` без последнего сегмента, обязан быть узлом; `parent` узла — производное поле, у корня его нет. Корней может быть несколько.
- Порядок `id` — посегментный, по кодовым единицам: `a` < `a/b` < `a-b`, поэтому `example/todo` идёт раньше `example-ui`.

## 3. Документ формата 1

`GraphDocument.of(graph, { app })` или `AppGraph.document(version)`; `serialize()` — JSON с отступом 2 и переводом строки в конце. Ключи — в порядке таблиц.

| Ключ | Что |
|---|---|
| `format` | `1` (`GRAPH_FORMAT`) |
| `app` | `{ name, version }` — данные вызывающего, с корнями графа не сверяются |
| `providers` | `[{ name, version, nodeKinds, edgeKinds }]` — запись на пару `(name, version)`; виды — `{ kind, label, description }`, оба списка есть всегда; схем свойств в документе нет |
| `externals` | внешние ссылки — концы рёбер, которые не узлы |
| `nodes` | узлы |
| `edges` | рёбра |

| Элемент | Поля |
|---|---|
| узел | `id`, `kind`, `label`, `description`, `visible`, `parent` (у корня нет), `provider`, `props` |
| ребро | `kind`, `from`, `to`, `provider`, `props` |

**Порядок и детерминизм.** Узлы и `externals` — по `id` (§2); рёбра — `from`, `kind`, `to`; поставщики — `name`, `version`; виды в записи поставщика — `kind`. Сравнение текста — по кодовым единицам, без локали. Ключи внутри `props` не пересортировываются. Одинаковый граф даёт одинаковую строку; времени, путей и окружения в документе нет.

## 4. Подъём и монтирование

- **Подъём** — чтение, в документ не пишется; результат — `LiftedEdge { kind, from, to, sources }`: одна запись на тройку, `sources` — исходные рёбра в каноническом порядке, петли отбрасываются.
  - `liftToKind(kind)` — конец поднимается к ближайшему узлу вида `kind` на пути к корню (включая сам конец); конец без такого предка и внешний конец остаются как есть.
  - `liftToDepth(depth)` — к приставке `id` из `depth` сегментов; работает по пути и усекает в том числе внешние `id`. `depth` — целое ≥ 1.
- **Монтирование** `host.mount(child, under)` — новый граф: узлы `child` и внутренние концы его рёбер получают приставку `under/`, внешние концы остаются как есть. Внешняя ссылка любого из двух графов, совпавшая с узлом результата, перестаёт быть внешней. Ссылка разрешается в графе, куда монтируют, поэтому вложенное монтирование зависит от порядка. Виды поставщиков двух графов сверяются (`kind-conflict`, §6).
- **Записи поставщиков** при соединении графов: одинаковые `(name, version)` с равными списками видов — одна запись; один `name` с разными `version` — две записи без сверки между собой.

## 5. Поставщик домена

`DomainProvider` (имя — `dmg-core`, `DOMAIN_PROVIDER`; версия — версия пакета) строит вклад по `AppDef` и Def его модулей; правил у него нет. `AppGraph` (`{ def, providers? }` — тип `GraphApp`) добавляет его первым, затем поставщиков из `providers`: `build()` — граф, `document(version)` — документ с `app` = имя `AppDef` и `version`.

**Дерево `id`** — FQN домена под корнем приложения, `/` вместо `.`. Правила дерева — только в `DomainIds` (`new DomainIds(appDef)`: `app()`, `module`, `aggregate`, `operation`, `event`, `error`, `rule`); другие поставщики ссылаются на узлы домена через него.

| Узел | `id` |
|---|---|
| приложение | `<app>` |
| модуль | `<app>/<m>` |
| агрегат | `<app>/<m>/<a>` |
| UC, ER, Job | `<app>/<m>/<op>` — ребёнок модуля, с агрегатом связывает ребро `touches` |
| событие | `<app>/<m>/<a>/<короткое имя>` |
| ошибка | `<app>/<m>/<a>/<CODE>` |
| доменное правило | `<app>/<m>/<a>/<name>` — агрегат-владелец ошибки правила |

Имена в одном пространстве (модули в приложении; агрегаты и операции в модуле; события, ошибки и правила в агрегате) уникальны — MAN-16, иначе сборка падает `duplicate-node`. Имя приложения — сегмент `id` (MAN-15).

**Виды узлов** (`DOMAIN_KINDS`; имя вида — `dmg` Def). Схемы свойств строгие: лишний ключ — `invalid-props`; ключ без значения не пишется; вложенное — JSON-форма `normalize()` Def.

| `kind` | `label` | `props` |
|---|---|---|
| `app` | Приложение | `scale?` |
| `module` | Модуль | `external` |
| `aggregate` | Агрегат | `state`, `statuses?`, `transitions?` |
| `useCase` | UC | `exposed`, `type` (`command` \| `query`), `callers`, `personal`, `policy`, `input`, `output` |
| `eventReaction` | Реакция на событие | `{}` |
| `job` | Задание | `schedule` |
| `event` | Событие | `name` (FQN), `exposed`, `payload` |
| `error` | Ошибка | `kind` (из `ERROR_KINDS`), `payload?` |
| `domainRule` | Доменное правило | `{}` |

Policy, `RulesDef`, статусы и переходы узлами не становятся (статусы и переходы — в `props` агрегата). Доменное правило — узел, только если на него ссылается UC.

**Виды рёбер** — без свойств (`props` — `{}`); `from` — кто объявил ссылку; повтор ссылки в Def даёт одно ребро.

| `kind` | `label` | Откуда → куда |
|---|---|---|
| `dependsOn` | Зависит от | модуль → модуль |
| `touches` | Работает с агрегатом | UC (управляет), ER (трогает), Job (просматривает) → агрегат |
| `calls` | Вызывает UC | операция → UC другого модуля |
| `emits` | Публикует | операция → событие |
| `subscribes` | Подписана на | ER → событие |
| `failsWith` | Отказывает ошибкой | UC → ошибка; доменное правило → ошибка |
| `checks` | Проверяет правило | UC → доменное правило |

**Связи модулей** — `liftToKind('module')`, обратные связи — `incoming`; все поднятые рёбра читаются «зависит от» (подписка — от модуля реакции к модулю события).

**Внешние `id`** — под корнем `dmg-core`, узлами не становятся и видны в `externals`:
- базовая ошибка пакета (`CoreErrors`) — `dmg-core/<CODE>`;
- Def вне модулей приложения — `dmg-core/orphan/<dmg>/<name>`: событие — по FQN, ошибка — по коду (о таких Def сообщает MAN-06); правило с базовой ошибкой пакета — тоже внешний `id`.

## 6. Ошибки `GraphError`

Исключение с `code` (`GraphErrorCode`), не `Result`; текст называет элемент и поставщика.

| `code` | Когда |
|---|---|
| `duplicate-provider` | второй поставщик с тем же `name` в одном `GraphBuilder` (в том числе `dmg-core` в `providers` `AppGraph`) |
| `duplicate-kind` | вид повторён в своём пространстве в одном `GraphBuilder` — тем же или другим поставщиком |
| `kind-conflict` | при соединении графов (`mount`): одноимённый вид у поставщиков с разными `name`; одинаковые `(name, version)` с разными списками видов |
| `unknown-kind` | элемент вида, который никто не зарегистрировал |
| `invalid-props` | свойства не по схеме вида; непустые свойства у вида без схемы |
| `invalid-id` | сегмент `id` или имя вида не по правилу §2; пустое имя поставщика |
| `duplicate-node` | `id` уже занят узлом |
| `unknown-parent` | родитель узла — не узел графа |
| `unknown-source` | начало ребра — не узел графа |
| `duplicate-edge` | ребро с той же тройкой `(kind, from, to)` уже есть |
| `unknown-mount` | узла монтирования нет в графе |
| `invalid-depth` | глубина подъёма или приставки — не целое ≥ 1 |

В `arch:check` несобранный граф при правилах поставщиков — нарушение ARC-13, а не исключение (D-97).

## 7. Команда `dmg-core graph`

```sh
dmg-core graph <файл> [--out <путь>]
```

- **Файл** — `export default { def, providers? } satisfies GraphApp`: `AppDef` и поставщики сверх домена (поставщика домена добавляет `AppGraph`). Образцы — `src/testing/example/example.graph.ts` (`ExampleGraph` в `dmg-core/testing`) и `src/testing/example/screen/screen.graph.ts`; в каркасе `init` — `scripts/<имя>.graph.ts`, скрипт `bun run graph`.
- **Вывод** — `graph.json` в каталоге запуска или путь `--out` (каталоги создаются); `--out=путь` — неизвестный флаг. Версия в `app` — `version` из `package.json` каталога запуска. `graph.json` — артефакт сборки, в git не хранится.

| Выход | Сообщение |
|---|---|
| 0 | `Записан: <путь> (узлов — N, рёбер — M, внешних ссылок — K)`; `<путь>` — как в `--out` |
| 2 (и справка `USAGE`) | `graph: не указан файл приложения`, `graph: неизвестный флаг <флаг>`, `graph: лишний аргумент <аргумент>`, `graph: у флага --out нет значения` |
| 1 | `graph: нет файла <файл>`; `graph: <файл> — нужен export default { def: AppDef, providers?: GraphProvider[] }`; `graph: в package.json проекта нет version`; `graph: <текст GraphError>` (без стека) |

Пример — образец расширения из корня пакета:

```sh
$ bun src/cli/main.ts graph src/testing/example/screen/screen.graph.ts --out /tmp/g.json
Записан: /tmp/g.json (узлов — 32, рёбер — 39, внешних ссылок — 0)
```

В документе — поставщики `dmg-core` и `example-screen`; первый узел — корень `example` вида `app`, последние — `example-ui` и `example-ui/tasks`.
